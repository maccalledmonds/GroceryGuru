# GroceryGuru Feature: Hybrid Recipe Recommendation System

## Phases

### Phase 0: Canonical Ingredient Dataset

#### Goal:
Create a structured canonical ingredient dataset that supports reliable normalization and matching.

#### Requirements:
- Each ingredient must have:
  - unique `id`
  - `canonical_name`
  - list of `aliases`

#### Data Structure:

{
  id: string,
  canonical_name: string,
  aliases: string[]
}

#### Example:

[
  {
    id: "ing_001",
    canonical_name: "tomato",
    aliases: ["tomatoes", "cherry tomato", "roma tomato"]
  },
  {
    id: "ing_002",
    canonical_name: "chicken",
    aliases: ["chicken breast", "chicken thighs", "chicken meat"]
  },
  {
    id: "ing_003",
    canonical_name: "onion",
    aliases: ["onions", "red onion", "white onion"]
  }
]

#### Subtasks:
- Design schema for ingredient dataset
- Populate initial dataset with common ingredients
- Expand dataset to include:
  - proteins
  - vegetables
  - grains
  - oils
  - condiments
  - common multi-word ingredients (e.g. "soy sauce", "olive oil")

#### Constraints:
- No duplicate canonical ingredients
- Aliases must map to exactly one canonical ingredient
- Preserve multi-word ingredients (e.g. "soy sauce" should NOT become "soy")

---

### Phase 1: Ingredient Normalization System

#### Goal:
Convert raw ingredient strings into canonical ingredient representations using the dataset from Phase 0.

#### Core Principle:
Deterministic normalization FIRST, semantic handling SECOND.

---

#### Normalization Pipeline (must follow order):

1. Lowercase conversion  
2. Remove punctuation  
3. Remove descriptors:
   - fresh, chopped, diced, organic, large, small, etc.

4. Singularization:
   - tomatoes → tomato  
   - eggs → egg  

5. Alias matching:
   - Match cleaned string against dataset aliases

6. Canonical mapping:
   - Map to `canonical_name` and `id`

---

#### Output Format:

{
  raw: string,
  normalized: string,
  canonical_name: string,
  canonical_id: string | null
}

---

#### Subtasks:
- Implement preprocessing pipeline
- Implement alias lookup system
- Handle multi-word ingredients correctly
- Ensure deterministic mapping

---

#### Constraints:
- DO NOT hallucinate ingredients
- If no match is found:
  - return cleaned ingredient
  - set canonical_id = null

- DO NOT rely on LLM for normalization
- Avoid embedding-based matching as primary method

---

#### Edge Cases:
- "ice cream" → must remain "ice cream"
- "soy sauce" → must remain intact
- "extra virgin olive oil" → "olive oil"
- plural + descriptor combinations

---

### Phase 2: Ingredient Matching Core

- Exact match recipes that are unique from each other
- Generated by llama-3.1-8b-instant LLM using available ingredients
- MUST use canonical ingredients for matching (not raw strings)

---

### Phase 3: Similar Recipe Retrieval

- Recommend recipes from recipe database requiring minimal extra ingredients
- Use canonical ingredient overlap (not raw string comparison)

---

### Phase 4: Scoring System

- Rank recipes based on:

  score = (# matched canonical ingredients) / (total required ingredients)

- Penalize missing ingredients

---

### Phase 5: API Layer

- Endpoint returns:

{
  exact: [],
  similar: [
    {
      recipe,
      missing_ingredients: [],
      score: number
    }
  ]
}

---

### Phase 6: Frontend Integration

- Display 2 sections:
  - "Cook Now" (exact matches)
  - "Almost There" (similar recipes)

---

### Phase 7: Testing & Edge Cases

- Empty pantry
- Duplicate ingredients
- Large ingredient lists
- Ingredients not in dataset
- Ambiguous ingredients

---

## Notes

- ALL downstream systems MUST rely on canonical ingredients
- Raw ingredient strings should NEVER be used for matching directly
